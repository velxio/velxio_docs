[WiFi接続](/docs/ja/wifi-iot/esp32-wifi/)により、シミュレートされたESP32は実際のIoTワークロードを実行できます。サンプルギャラリーには、すぐに開いて実行できる**ESP32 MQTT**カテゴリが用意されています。

## MQTT

標準のPubSubClientフローはそのまま動作します：`Velxio-GUEST`に参加し、公開ブローカーに接続し、パブリッシュおよびサブスクライブします。ギャラリーのMQTTサンプルを開いて、以下を確認してください：

- タイマーによるセンサー測定値のパブリッシュ、
- トピックへのサブスクライブと受信メッセージによる出力の駆動、
- 公開ブローカーに対する完全な双方向ダッシュボード交換。

ブローカーは実際のものなので、シミュレートされたボードのメッセージが、任意のMQTTクライアントを使用してスマートフォンやラップトップに届くのを確認でき、さらにボードにパブリッシュして戻すこともできます。

## HTTP

`HTTPClient`（Arduino）および`urequests`（MicroPython）は実際のエンドポイントに対して動作します：REST APIの取得、ファイルのダウンロード、Webhookの送信。ペイロードは適切なサイズに保ってください — エミュレートされたチップには実際のチップと同じRAM制限があります。

## 注意事項と制限

- APは**オープン**（パスワードなし）で、NATインターネットアクセスを提供します — インターネットからシミュレートされたボードへのインバウンドアクセスはありません。
- DNS、TCP、UDP、TLSはハードウェアと同様に動作します。負荷の高いTLSハンドシェイクは実際のエミュレートCPU時間を消費するため、少し時間がかかることがあります。
- 接続が失敗した場合は、まずシリアルモニターを確認してください — WiFiスタック自体のログ行（`wifi:connected`、`got ip`）が、どのステップが実行されなかったかを示します。
