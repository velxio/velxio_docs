Платы ESP32 в Velxio поставляются с **рабочим WiFi**: эмулируемое радио
видит открытую точку доступа с именем **`Velxio-GUEST`**, подключается,
получает IP-адрес по DHCP и выходит в интернет через NAT-шлюз эмулятора.
Точно такой же скетч работает на физическом чипе.

## Arduino

```cpp
#include <WiFi.h>

const char* WIFI_SSID = "Velxio-GUEST";  // открытая точка доступа, без пароля

void setup() {
  Serial.begin(115200);
  WiFi.begin(WIFI_SSID);
  while (WiFi.status() != WL_CONNECTED) { delay(250); Serial.print("."); }
  Serial.printf("\nConnected! IP: %s\n", WiFi.localIP().toString().c_str());
}
```

Монитор последовательного порта показывает знакомые сообщения `wifi:connected`
и информацию о DHCP-аренде — потому что это _настоящий_ стек WiFi:

![Монитор последовательного порта во время подключения WiFi](../../../../assets/docs/wifi-iot/serial-wifi.png)

## MicroPython

```python
import network

WIFI_SSID = "Velxio-GUEST"

sta = network.WLAN(network.STA_IF)
sta.active(True)
sta.connect(WIFI_SSID)
while not sta.isconnected():
    pass
print("Connected, IP:", sta.ifconfig()[0])
```

## Собственные сети: пользовательские точки доступа

С планом Maker вы не ограничены встроенными демонстрационными сетями: добавьте
часть **WiFi Access Point** на холст (найдите «WiFi Access Point» в
браузере компонентов), и эмулируемое радио будет транслировать **ваш SSID**.
Скетч подключается к сети, которую он фактически называет:

```cpp
WiFi.begin("HomeNet", "");   // SSID на вашей части Access Point
```

У части нет выводов — это не электрический компонент, это эфир.
Как только проект содержит хотя бы одну часть точки доступа, встроенные
сети замолкают: сканирование показывает ровно то, что определено на холсте.
Добавьте несколько частей, чтобы протестировать интерфейс выбора сети;
каждая имеет свой канал и уровень сигнала, а повторные сканирования
добавляют несколько дБ дрожания, как у реальных сетей.

Два свойства стоит знать:

- **Internet** — отключите его, и сеть станет изолированной: плата
  подключается и получает IP по DHCP, но маршрутизация наружу отсутствует.
  Это сценарий подготовки / captive-portal, теперь тестируемый в симуляторе.
- **Password** — хранится вместе с частью и отображается на её карточке,
  но сеть по-прежнему транслирует открытую аутентификацию, пока не появится
  эмуляция WPA2. Скетчи, передающие пароль, всё равно подключаются.

Загруженная прошивка тоже получает преимущества: бинарный файл, собранный
в другом месте, подключается к сети, которую он называет, если часть точки
доступа транслирует этот SSID — пересборка не требуется.

Попробуйте в один клик: пример из галереи **Connect to your own WiFi
network** открывается с уже размещённой на холсте частью.

## Панель WiFi

Иконка WiFi на панели инструментов — это разделённая кнопка. Сама иконка
сохраняет действие в один клик — при наличии IP она открывает веб-сервер
платы через IoT-шлюз. Небольшой треугольник рядом открывает **панель WiFi**:

- сети, находящиеся в эфире (ваши точки доступа или встроенный набор),
  с отметкой подключённой;
- состояние подключения платы и IP-адрес;
- **Download PCAP** — трафик 802.11 текущего запуска в виде файла захвата,
  который Wireshark открывает напрямую (управляющие кадры, DHCP, DNS, TCP,
  с метками симулированного времени). Ничего не загружается; файл создаётся
  в вашем браузере;
- сопряжение с [локальным сетевым шлюзом](/docs/ru/wifi-iot/local-gateway/).

## Что доступно

После подключения стандартные TCP/UDP-сокеты, HTTP-клиенты и MQTT-библиотеки
работают с **реальными серверами в интернете** — публичными MQTT-брокерами,
REST API, NTP. См. [MQTT и HTTP](/docs/ru/wifi-iot/mqtt-http/) для полных
проектов.

## Какие платы

WiFi доступен во всём семействе симулированных ESP32 — классические платы
ESP32, ESP32-S3, ESP32-C3, ESP32-C6 и ESP32-C5 (и их варианты XIAO / Nano /
M5Stack). Состояние Bluetooth-рекламы также сообщается для скетчей,
инициализирующих BLE.
