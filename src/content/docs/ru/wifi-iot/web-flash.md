Когда ваш проект работает в симуляторе, вы можете перенести его на **реальную плату** без установки чего-либо: Velxio прошивает скомпилированную прошивку через USB прямо из браузера.

## Требования

- Браузер на основе Chromium (Chrome или Edge). Прошивальщик использует API Web Serial и WebUSB браузера, которых нет в Firefox и Safari. Для плат семейства Pico там по-прежнему доступна кнопка **Download .uf2** (см. ниже).
- USB-кабель с поддержкой передачи данных для вашей платы.
- Закройте все остальные программы, использующие порт (мониторы последовательного порта, IDE, picotool): браузеру нужен монопольный доступ.

![Диалог прошивки с выбором USB-порта](../../../../assets/docs/wifi-iot/flash-modal.png)

## Прошивка

1. Щелкните правой кнопкой мыши по плате на холсте и выберите **Flash to real board** (Прошить на реальную плату).
2. Нажмите **Connect & flash** (Подключиться и прошить). Браузер спросит, какому USB-устройству предоставить доступ; выберите вашу плату.
3. Velxio использует сборку, уже созданную для этой платы (тот же двоичный файл, который запускал симулятор). Если код изменился с тех пор, он сначала перекомпилируется, и вывод компилятора будет транслироваться в диалоговое окно.
4. Следите за индикатором выполнения; когда он завершится, плата перезагрузится в ваш проект.

Диалог выбирает протокол для целевого устройства:

| Семейство | Как записывается | Плата должна быть |
| --- | --- | --- |
| ESP32, S3, C3, C6 | esptool через последовательный порт, объединенный `.bin` | подключена; удерживайте BOOT, если она не отвечает |
| Arduino Uno, Nano, Mega, ATtiny85 | STK500 через загрузчик платы, `.hex` | подключена (ATtiny85: через Arduino с прошивкой ArduinoISP) |
| Raspberry Pi Pico, Pico W, Pico 2, платы Pimoroni RP2040 / RP2350 | PICOBOOT через WebUSB, `.uf2`, созданный picotool | в режиме **BOOTSEL** (следующий раздел) |

## Платы семейства Pico: сначала BOOTSEL

RP2040 или RP2350 программируется через свой загрузчик — отдельный USB-интерфейс, который чип показывает только в режиме **BOOTSEL**. Два способа попасть в него:

- **Вручную**: удерживайте кнопку BOOTSEL при подключении платы, затем отпустите. Плата смонтируется как USB-накопитель с именем `RPI-RP2` (RP2040) или `RP2350`.
- **Из диалога**: в диалоге прошивки для этих плат есть кнопка **Reboot into bootloader over USB** (Перезагрузиться в загрузчик через USB). Она работает, когда на плате запущен скетч, созданный Velxio (ядро Arduino перезагружается при открытии порта на скорости 1200 бод) или MicroPython (REPL выполняет `machine.bootloader()`). Браузер запрашивает последовательный порт платы, плата отключается и возвращается как загрузчик. Затем нажмите **Connect & flash** и выберите устройство `RP2 Boot` / `RP2350 Boot`.

Два щелчка, два запроса разрешений: последовательный порт для перезагрузки и USB-устройство для записи. После того как плата находится в режиме BOOTSEL, для последующих прошивок нужен только второй.

Диалог отказывается записывать образ, не соответствующий чипу, который ответил (сборка для RP2350 на RP2040, сборка для RISC-V на конфигурации ARM), до начала стирания, проверяет каждый байт после записи и перезагружает плату в программу.

### Windows и RP2040: установите WinUSB один раз

Загрузчик RP2040 не содержит дескриптора драйвера Windows, поэтому браузер не может получить к нему доступ, пока не будет привязан WinUSB. Настройка выполняется один раз:

1. Переведите плату в режим BOOTSEL и подключите ее.
2. Загрузите и запустите [Zadig](https://zadig.akeo.ie).
3. Выберите `RP2 Boot (Interface 1)` из списка (Options, List All Devices, если он скрыт), выберите **WinUSB** в качестве драйвера и нажмите **Install Driver**.

Платам RP2350 (Pico 2, Pico 2 W, платы Pimoroni "Pico 2 W Aboard" Unicorns, Badger 2350) ничего не нужно: их загрузчик содержит дескриптор, и Windows сама привязывает WinUSB. В macOS ничего не нужно ни для одного чипа.

### Linux: правило udev

Linux по умолчанию предоставляет USB-устройства root-пользователю. Создайте `/etc/udev/rules.d/99-velxio-rp2.rules` со следующим содержимым:

```
SUBSYSTEM=="usb", ATTRS{idVendor}=="2e8a", MODE="0666", TAG+="uaccess"
```

затем выполните `sudo udevadm control --reload-rules && sudo udevadm trigger` и переподключите плату. Для последовательного порта, используемого на этапе перезагрузки, также требуется обычное членство в группе `dialout`.

### Любой браузер: загрузка .uf2

Диалог прошивки для платы семейства Pico всегда предлагает **Download .uf2** (в Firefox и Safari, где браузер не может прошивать, это весь диалог). Сохраните файл, переведите плату в режим BOOTSEL и перетащите файл на диск `RPI-RP2` / `RP2350`: плата перезагрузится в ваш скетч, как только закончится копирование.

### Проекты MicroPython на Pico

Диалог загружает `.py`-файлы проекта через REPL и перезагружается в `main.py`. Сам MicroPython уже должен быть на плате: это `.uf2`, который вы один раз перетаскиваете на диск BOOTSEL (платы Pimoroni поставляются с ним; загрузки на [pimoroni-pico-rp2350](https://github.com/pimoroni/pimoroni-pico-rp2350/releases) и [micropython.org](https://micropython.org/download/)).

## Устранение неполадок

- **"No board in BOOTSEL mode was found"** (Плата в режиме BOOTSEL не найдена): выбор устройства был пуст. Используйте кнопку перезагрузки или удерживайте BOOTSEL при подключении, затем подключитесь снова.
- **"The board in BOOTSEL is an RP2040 but this project is built for RP2350"** (Плата в BOOTSEL — RP2040, но этот проект собран для RP2350): Pimoroni продавала Stellar и Galactic Unicorn с Pico W (RP2040) до января 2025 года и с Pico 2 W (RP2350) с тех пор. Проверьте маркировку на вашем устройстве и выберите соответствующую плату в редакторе.
- **"Could not claim the USB device"** (Не удалось получить доступ к USB-устройству) в Windows с RP2040: выполните шаг с Zadig выше. В Linux: правило udev выше.
- **Перезагрузка через последовательный порт не сработала**: скетч, собранный с отключенным USB-стеком, нельзя перезагрузить через USB. Удерживайте BOOTSEL при подключении.

## Сначала симулируйте, потом прошивайте

Это замыкает цикл, который делает Velxio полезным для реальной работы: быстро итерируйте в симуляторе (без кабеля, без износа оборудования, мгновенные сбросы), затем прошивайте тот же самый собранный артефакт, когда он ведет себя правильно.
