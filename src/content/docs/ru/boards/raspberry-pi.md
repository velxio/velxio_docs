Семейство Raspberry Pi выполняет **Python-скрипты для схемы на холсте**. В отличие от плат микроконтроллеров, здесь нечего компилировать: вы пишете скрипт, нажимаете **Run**, и Velxio выбирает один из двух движков для его выполнения. Ни один из движков не является рабочим столом Raspberry Pi OS, поэтому прочитайте эту страницу, прежде чем предполагать, что руководство, написанное для реального оборудования, заработает без изменений. Большинство из них работают: таблицы ниже были проверены на живом продукте, часть за частью, 2026-09-19.

| Плата                         | Профиль CPU         |
| ----------------------------- | ------------------- |
| **Raspberry Pi Zero / 1 / 2** | Класс ARM Cortex-A7 |
| **Raspberry Pi 3**            | Cortex-A53          |
| **Raspberry Pi 4**            | Cortex-A72          |
| **Raspberry Pi 5**            | Cortex-A76          |

Любой может разместить Pi на холсте и собрать схему вокруг него. Для **запуска** нужен платный план или одна из **трёх бесплатных пробных сессий по 15 минут**, которые получает каждая учётная запись для семейства Pi (см. [планы](/docs/ru/getting-started/plans/)). Если в проекте нет ничего, что Pi может выполнить, например скетч Arduino `.ino` на плате Pi, об этом сообщается до того, как будет потрачена пробная сессия.

## Два движка

### Instant (в вашем браузере)

По умолчанию. Ваш скрипт выполняется на интерпретаторе Python, скомпилированном в WebAssembly внутри вкладки, запускается за несколько секунд и не требует ничего от серверов Velxio. Запись в пины напрямую достигает холста, поэтому светодиод загорается в момент выполнения `led.on()`. I2C, SPI и 1-Wire присутствуют в виде файлов устройств, которые есть у Pi (`/dev/i2c-1`, `/dev/spidev0.0`, дерево `/sys/bus/w1/devices`), обслуживаемых подключёнными на холсте компонентами, поэтому настоящие `smbus2`, `w1thermsensor` и Adafruit Blinka работают без изменений.

Это обычный интерпретатор, а не операционная система: здесь нет оболочки, нет `subprocess`, нет сырых сокетов. Скрипт, который запрашивает что-то из этого, перенаправляется в движок Linux; **чип движка** на панели инструментов показывает, какой движок будет выполнять скрипт, а когда это Linux — файл и строку, которые этого потребовали.

### Linux (на серверах Velxio)

Настоящий Linux-гость, загруженный в QEMU (`-M virt`, с профилем CPU вашей платы), доступ к которому вы получаете через последовательную консоль в рабочей области. Будьте точны в том, что это такое:

- **Alpine Linux**, а не Raspberry Pi OS. `python3` и `pip` установлены; `apt`, `raspi-config`, рабочий стол и инструменты прошивки Pi отсутствуют.
- **Нет сети** изнутри гостя, намеренно. `pip install` не может достичь PyPI; пакеты поступают через `requirements.txt` (ниже).
- **Шинные интерфейсы разъёмов — это настоящие файлы устройств.** `/dev/i2c-1`, `/dev/spidev0.0` и `/dev/spidev0.1` отвечают на те же системные вызовы, что и на Pi, поэтому библиотека, которая открывает их сама (Adafruit Blinka), программа на C или ваш собственный код с `ioctl` общаются с компонентами на холсте. Адрес, который никто не занимает, завершается ошибкой `OSError: [Errno 121] Remote I/O error`, как на реальном оборудовании.
- **UART разъёма — это настоящий последовательный порт.** `/dev/serial0` (также `/dev/ttyAMA0` и `/dev/ttyS0`) — это подлинный tty, управляемый неизменённым pyserial: `serial.tools.list_ports`, `select()` на порту и `cat /dev/serial0` работают, а байты идут к тому, что подключено к GPIO14 и GPIO15 на холсте.
- Здесь **нет** `/dev/gpiomem`, `/dev/gpiochip0`, `/sys/class/gpio` или дерева 1-Wire. GPIO работает через `RPi.GPIO` и `gpiozero`, которые здесь есть; `libgpiod`, `gpioinfo` и `pigpio` не с чем взаимодействовать.
- Загрузка занимает примерно 20–30 секунд, дольше, когда сервер занят; оверлей "Booting" отслеживает её. Сессия гостя завершается не позднее чем через **2 часа**.
- Гость запускает **`script.py`** из вашего проекта при загрузке. Назовите так ваш главный файл в режиме Linux (instant-движок выполняет первый найденный `.py`).

Кнопка **Linux terminal** в рабочей области закрепляет этот движок на остаток сессии, когда вам нужна оболочка, например чтобы просмотреть файлы или запустить скрипт вручную. Выбор не сохраняется вместе с проектом: откройте его завтра, и Run снова вернётся к ответу детектора. Всё, что может выполнить instant-движок, работает быстрее без него.

## Что работает, часть за частью

Каждая строка — это один скрипт, написанный так, как его пишет руководство по Pi, выполненный на живом продукте с подключённым на холсте компонентом, на Raspberry Pi 4. Строки с дисплеями проверяются на самом холсте: панель должна загореться, а не только скрипт завершиться.

| Что | Библиотека, которую использует скрипт | Instant | Linux |
| --- | --- | --- | --- |
| Светодиод и кнопка | `gpiozero` | Да | Да |
| Серво (PWM) | `gpiozero.Servo` | Да | Да |
| Акселерометр MPU6050 | `smbus2` | Да | Да |
| Часы реального времени DS3231 | `smbus2` | Да | Да |
| Датчик давления BMP280 | `smbus2` | Да | Да |
| Температура и влажность SHT31 | `smbus2` | Да | Да |
| 16-канальный драйвер PWM PCA9685 | `smbus2` | Да | Да |
| АЦП ADS1115 | `smbus2` | Да | Да |
| LCD 16x2, I2C-модуль | `smbus2` или `RPLCD.i2c` | Да | Да |
| LCD 16x2, параллельный (RS, E, D4–D7) | `RPLCD.gpio` | Да | Да |
| OLED SSD1306 | `smbus2` | Да | Да |
| OLED SSD1306 | `luma.oled` | Да | Да |
| OLED SSD1306 | Adafruit Blinka + `adafruit_ssd1306` | Да | Да |
| TFT ILI9341 | `spidev` | Да | Да |
| Карта microSD (режим SPI) | `spidev` | Да | Да |
| Температурный щуп DS18B20 | 1-Wire sysfs, `w1thermsensor` | Да | **Нет** |
| Потенциометр напрямую на GPIO | | Нет (см. ниже) | Нет |

Строки с OLED и LCD также были проверены на Raspberry Pi Zero в движке Linux, который представляет собой 32-битного гостя с собственным образом.

## Что не работает

- **Аналоговый вход на GPIO.** У Raspberry Pi **нет АЦП**, в том числе на реальном оборудовании. Потенциометр, фоторезистор или датчик пульса, подключённые напрямую к GPIO, всегда считывают только высокий или низкий уровень, и консоль выполнения об этом сообщает. Поставьте **ADS1115** (I2C) или **MCP3008** (SPI) между датчиком и Pi, точно так же, как на стенде; оба есть в каталоге, а в галерее есть пример с MCP3008 и потенциометром.
- **1-Wire в движке Linux.** Ядро гостя не поддерживает 1-Wire, поэтому скрипт для DS18B20 не находит там `/sys/bus/w1/devices`. Это работает в instant-движке, где в любом случае выполняется скрипт, который только импортирует `w1thermsensor`.
- **Камера в движке Linux.** `picamera2` работает в instant-движке, получая данные с вашей веб-камеры или тестового шаблона; у гостя нет камеры.
- **`pigpio`, `libgpiod` / `gpiod`, `/dev/gpiomem`.** Ни демона, ни символьного устройства GPIO ни в одном из движков. Используйте `RPi.GPIO` или `gpiozero`.
- **Скрипт, скопированный из руководства по MicroPython.** `import machine`, `from gpio_lcd import GpioLcd` и подобные существуют на Pico или ESP32, но не на плате, которая выполняет полный Python. Консоль называет эквивалент для Pi (`gpiozero`, `RPLCD`, `luma.oled`, `w1thermsensor`) вместо предложения установить пакет.
- **PyTorch, TensorFlow.** Гигабайты, и здесь нечем их ускорять. Они отклоняются с этим объяснением.

## Модули Python в каждом движке

Оба движка поставляются со стандартной библиотекой. "Предустановлен" означает, что он работает сразу после строки `import`, без `requirements.txt`, так же, как Raspberry Pi OS имеет свои аппаратные библиотеки в образе.

| Модуль | Instant (браузер) | Linux (гость) |
| --- | --- | --- |
| `RPi.GPIO` | Предустановлен | Предустановлен |
| `gpiozero` | Предустановлен | Предустановлен (2.0.1) |
| `smbus2` / `smbus` | Предустановлен (настоящая библиотека) | Предустановлен |
| `spidev` | Предустановлен | Предустановлен |
| `serial` (pyserial) | Только пути UART Pi | Настоящий pyserial 3.5 на настоящем tty |
| `w1thermsensor` | Предустановлен | Недоступен (нет 1-Wire) |
| `luma.core`, `luma.oled`, `luma.lcd` | Предустановлен | Предустановлен |
| `RPLCD` | Предустановлен | Предустановлен |
| `ST7789` | Предустановлен | Предустановлен |
| `board`, `busio`, `digitalio` (Adafruit Blinka) | Предустановлен | Предустановлен |
| `adafruit_ssd1306`, `adafruit_rgb_display` | Предустановлен | Предустановлен |
| `PIL` (Pillow), `numpy` | Предустановлен | Предустановлен (Pillow 10.3, numpy 1.25) |
| `cv2` (OpenCV) | Да | Нет (нет сборки для гостя) |
| `picamera2` | Да, через вашу веб-камеру | Нет |
| `velxio_screen` | Да | Да |
| `requests` / `urllib` | Да, через прокси-выход Velxio со списком разрешённых | Нет сети |
| Всё остальное | Через `requirements.txt` | Через `requirements.txt` |

Шрифты DejaVu находятся в госте по пути, который использует Raspberry Pi OS (`/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf`), потому что руководства по дисплеям жёстко прописывают его.

```python
from luma.core.interface.serial import i2c
from luma.core.render import canvas
from luma.oled.device import ssd1306

import time

device = ssd1306(i2c(port=1, address=0x3C))
with canvas(device) as draw:
    draw.text((10, 20), "Hello from a Pi", fill="white")

# luma clears the panel when the script ends, as it does on hardware,
# so keep the script alive for as long as the text should stay up.
while True:
    time.sleep(1)
```

### Другим сторонним пакетам нужен `requirements.txt`

Добавьте файл `requirements.txt` рядом с вашим скриптом, по одному пакету на строку; Velxio разрешает его перед запуском и сообщает вам в консоли выполнения, что было установлено. Когда скрипт импортирует отсутствующий пакет, консоль предлагает строку для добавления, а кнопка записывает её за вас. Какой движок может принять пакет, зависит от того, как он собран:

- Чистый Python-пакет (wheel `py3-none-any`) работает в обоих движках.
- Пакет с скомпилированным кодом работает в **instant**-движке, когда среда выполнения браузера его поставляет (numpy, pillow, opencv-python, scikit-learn и другие), и в движке **Linux** только если в PyPI есть для него wheel **musl aarch64** (numpy, pandas, scipy и psutil — есть). Пакеты, которые публикуют только glibc-колёса `manylinux`, не могут быть установлены в госте.
- На Raspberry Pi Zero, 1 или 2 гость 32-битный, и в PyPI почти нет скомпилированных колёс для него: там оставайтесь с предустановленным или с чистыми Python-пакетами.
- Имена, которые гость уже предоставляет (`RPi.GPIO`, `smbus2`, `spidev`, `pyserial`, `gpiozero`), никогда не загружаются, поэтому `requirements.txt` из руководства, где они перечислены, не причиняет вреда.

Колёса учитываются в той же квоте хранилища, что и библиотеки Arduino.

## Файлы

**Панель файлов** в рабочей области Pi загружает скрипты и файлы данных в проект; в режиме Linux они копируются в домашний каталог гостя до запуска `script.py`.

## UNIHIKER M10

Образовательный SBC от DFRobot (Linux-плата со встроенным сенсорным экраном) работает на тех же двух движках, со своими собственными модулями `pinpong` и `unihiker` вместо прослоек для Pi. Это платная плата с собственными тремя пробными сессиями; найдите её в списке выбора рядом с семейством Pi.
